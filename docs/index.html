El concepto

Qué es y por qué existe

Mega Free Chat es una puerta de enlace local para conversar con modelos de costo cero de OpenRouter. Un servidor FastAPI descubre el catálogo, filtra los modelos con precio cero, los ordena con prioridad a proveedores chinos y transmite la respuesta por Server-Sent Events. La interfaz es un HTML con JavaScript embebido, sin frameworks ni compilación.

Apunta a quien quiere probar modelos gratuitos sin repartir cinco claves ni mantener una lista fija que caduca en días. El aporte es el criterio: el pool se reconstruye solo, el failover intenta el siguiente candidato y, cuando no hay cupo, la aplicación lo dice en lugar de fingir. Su límite es igual de claro: el failover no cubre errores del primer intento y el servicio no tiene autenticación.

03 — La idea

Un chat que no se cae cuando un modelo se cae

La gracia no es el chat: es la capa que elige, rota y mantiene la conversación viva cuando el proveedor gratuito falla.

El problema

Los modelos gratuitos de OpenRouter son excelentes hasta que desaparecen: 429, timeouts, modelos que dejan de estar disponibles. Un chat que depende de uno solo se rompe en la primera demo.

La solución

Un pool con prioridad china, failover automático y streaming SSE. Si el modelo activo falla, la pasarela elige otro y continúa la respuesta sin que el usuario recargue la página.

04 — El recorrido

Cómo funciona, paso a paso

El usuario escribe; la pasarela decide quién responde.

01

El navegador envía

La UI manda el historial al backend por HTTP y abre un stream SSE para la respuesta.

02

El pool elige

El backend consulta el catálogo de modelos gratuitos y prioriza los modelos chinos disponibles.

03

La respuesta fluye

Los tokens llegan por SSE y se pintan en la burbuja sin esperar al final.

04

Si falla, rota

Un error 429 o un timeout cambia el modelo y reintenta. El usuario ve una respuesta, no un stack trace.

Lo que no funcionó

Los tropiezos, documentados

Las primeras versiones existen para que estos errores no se repitan: cada una dejó una decisión de diseño verificable.

mega-free-chat

Failover que no atrapa el primer error

chat_stream es un generador: llamarlo no ejecuta la petición, así que el try/except del router envolvía la creación y no la iteración. Un 429 al abrir el stream se devolvía como error interno, sin cambiar de modelo. Se documentó como deuda y el arreglo consiste en primar el generador.

mega-free-chat

Configuración ignorada según el arranque

Los módulos leían os.getenv al importarse y load_dotenv() corría después, por lo que BACKOFF_SECONDS, POOL_REFRESH_SECONDS y OR_BASE_URL del .env se ignoraban con uvicorn server:app. run.sh exportaba las variables y ocultaba el problema. Quedó pendiente leer la configuración en runtime, porque el modo de arranque también define el comportamiento.

mega-free-chat

Lanzador en segundo plano revertido

Se agregó un lanzador de escritorio tipo interruptor para arrancar el servidor sin terminal. Dejaba procesos huérfanos, dos instancias peleando por el puerto 8000 y ninguna forma clara de saber cuál respondía. Se revirtió a run.sh en primer plano con exec y Ctrl+C.

mega-free-chat

Clasificación china por subcadena

La keyword ling, incluida por Ling/InclusionAI, matcheaba dentro de inkling y el panel mostraba modelos occidentales en el grupo chino. La lista pasó a expresiones regulares con límite de palabra. El cambio quedó documentado como lección sobre clasificar textos cortos.

Preguntas típicas

Lo que suelen preguntar

¿Es realmente gratis?

Usa modelos con costo cero de OpenRouter. Eso no garantiza disponibilidad ni cupo.

¿Dónde está la API key?

No se publica. Usá .env.example y tu propia clave.

¿Qué es el failover?

Si un modelo falla o no está disponible, se intenta el siguiente según la prioridad.

¿Por qué prioriza proveedores chinos?

Es una decisión del autor por latencia/disponibilidad; el orden es configurable.

¿Guarda conversaciones?

No hay base de datos en el gateway.
